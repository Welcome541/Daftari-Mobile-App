# الدفعة السابعة — المعاملات الإدارية وسلامة السلة

## التنفيذ

- `js/ledger-admin.js`: خدمات تعديل العميل، النقل إلى السلة، الاسترجاع، الأرشفة، والتفريغ عبر `LedgerEdits.commit`؛ لا تعتمد على DOM.
- `js/admin-actions.js`: أحداث الحسابات والعملات واللغة والتثبيت والأرشفة والسلة والصور. استُخرجت من `actions.js` و`screens.js` بدل إضافة مسؤوليات جديدة إليهما.
- تبديل الحساب وإنشاؤه وتعديله وتغيير العملة/اللغة ينتظر نجاح التخزين. لا تُمسح نماذج الإدخال أو الاختيارات بعد فشل الحفظ.
- الأرشفة والتثبيت وحذف العملاء والحركات واسترجاعها وتفريغ السلة تستخدم المعاملة نفسها. أُزيلت استدعاءات `save()` غير المنتظرة من ملفات واجهة الدفتر الحالية؛ يوجد اختبار يمنع عودتها إلى الملفات المنقولة. هذا لا يحول إعدادات `saveSec()` أو كل العمليات خارج الدفتر إلى معاملات.
- التراجع مرتبط بمعرّف الحساب الأصلي ونسخته بعد التعديل. يرفض عند تغير بيانات ذلك الحساب بدل الكتابة فوقها. يعيد حالة الأرشفة السابقة كما كانت، ولا يفك أرشفة عناصر كانت مؤرشفة قبل العملية.
- تفريغ السلة يحتفظ بالاعتمادات المباشرة والمتعدية للحركات الحية: دفعة → فاتورة محذوفة → عميل محذوف. يوضح للمستخدم بقاء عناصر مرتبطة. إذا أصبحت المجموعة كلها في السلة بلا مرجع من سجل حي، يمكن تفريغها. لا تُخترع سجلات لإصلاح روابط مفقودة تاريخيًا.
- الصور ترتبط بالحساب والعميل/كائن النموذج ومسار العرض وجيل الطلب. اكتمال قراءة صورة قديمة لا يكتبها في نموذج بديل أو حساب آخر. تغيير صورة موجودة ينتظر الحفظ ويقارن قيمتها السابقة. إزالة الصورة تبطل طلبات الصور الأقدم.
- حد ملف الصورة 8 MiB، وحد الأبعاد بعد فك الترميز 32 مليون بكسل، والتخزين النهائي JPEG بحجم 96×96. تُحرّر object URLs عند نجاح/فشل التحميل. حد الأبعاد بعد فك الترميز لا يمنع وحده استهلاك ذاكرة المفكك؛ قياسات الأجهزة تبقى مطلوبة.

## التحقق

`npm test`: **100/100** ناجحة، أي 17 اختبارًا إضافيًا عن الدفعة السابقة.

- فشل حفظ كل من العميل والحذف والاسترجاع والأرشفة والتفريغ يبقي الذاكرة والنسخة المحفوظة.
- التراجع بعد تبديل الحساب يستهدف الحساب الأصلي؛ التراجع المتقادم يُرفض.
- استرجاع السجل نفسه مرتين لا ينشئ نسخة مكررة؛ الأرشفة القديمة محفوظة عند التراجع.
- تفريغ السلة يحتفظ بسلسلة الاعتماد، ثم يسمح بحذف المجموعة غير المرجعية.
- رفض الحساب/العميل المفقود وتعديل حقول غير مسموح بها.
- فشل الحساب/العملة/اللغة لا يبدل حالة الدفتر أو يلغي الاختيار.
- الصور المتأخرة لا تعدّل نموذجًا بديلًا أو حسابًا آخر، وفشل إزالة الصورة يحفظ الصورة السابقة.
- إنشاء حساب يفشل دون إغلاق النموذج، ثم ينجح عند إعادة المحاولة برقم تسلسل ووحدة نقدية صالحين.

`git diff --check` نظيف. اختبارات الواجهة JSDOM والتخزين fake-indexeddb ليست بديلًا عن Android فعلي. لم تتغير Java ولم تُعد اختبارات JVM أو محاولة بناء APK في هذه الدفعة. عائق البناء المسجل في الدفعة السادسة (Java/تهيئة SDK) لم يُحل بعد.

## الباقي

- إزالة بقية inline handlers وتفكيك ملفات الشاشات الكبيرة؛ إزالة `save()` المباشر لا تعني اكتمال هذه المهمة.
- إصلاح واختبار WebAuthn/PRF. البروتوكول الحالي لا يزال يحتاج إعادة إرسال مدخل PRF الصحيح لكل اعتماد؛ لا نعتبر البصمة مكتملة بمجرد ذرية إعداداتها.
- تدقيق OCR والعامل وWASM وبيانات اللغة المحلية، وحدود QR وفك الضغط.
- مراجعة إعدادات الواجهة المحفوظة عبر `saveSec()` ومسارات الخطأ الخاصة بها.
- تجهيز سلسلة بناء Android، وإنتاج APK، ثم الترقية من بيانات حقيقية واختبارات Android 5/14 والأذونات والخلفية والدوران وموت العملية والنماذج والشاشات.

لا ادعاء بانعدام الأخطاء أو اكتمال الخطة الكلية؛ النتائج أعلاه تخص الاختبارات المنفذة فعلًا.
