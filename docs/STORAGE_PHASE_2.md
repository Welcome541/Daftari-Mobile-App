# الدفعة الثانية — إدارة الاستيراد والاسترجاع

## المنفّذ

1. `FileStorageManager` أصبح واجهة Android صغيرة نسبيًا: يقرأ URI واسم الملف ويفوّض العمل. لم يعد يحتوي فك ZIP أو ضغط TAR أو `renameTo`.
2. `ModelManager` مسؤول عن نموذج Vosk النشط: النسخ المحدود، الفحص، فك الأرشيف، تجهيز TAR، التثبيت، وإرجاع `ModelRecord`.
3. `ProjectManager` مسؤول عن استيراد حزمة HTML القديمة كملفات خاملة. لا يشغّل JavaScript مستوردًا، ولا يطبّق شروط نموذج Vosk على مشروع عادي.
4. `ArchiveExtractor` يفرض الحجم الفعلي وعدد العناصر والمسارات ويكتشف الأسماء المتطابقة بعد التطبيع. جذر Vosk يطبع قبل إزالة البادئة، والملفات الواقعة خارجه تُرفض بدل تركيب شجرة ملتبسة.
5. `ImportValidator.inspect` يفحص metadata دون فك غير محدود. القيم غير المعروفة والملفات المكررة والمجلدات المحملة ببيانات مرفوضة؛ فحص CRC الفعلي يتم عند القراءة بـ ZipInputStream.
6. `StorageFiles` يجمع النسخ المحدود، الإلغاء، التنظيف الذي لا يتبع symlink، وفحص مساحة القرص.
7. `ImportTransaction` يوفّر الاستبدال والاسترجاع لكل slot، تحت قفل مشترك لجميع عمليات الاستيراد داخل العملية.
8. الاسترجاع الأولي يعمل في عامل خلفي، لا على UI thread. تظهر شاشة انتظار؛ عند فشل الاسترجاع تظهر رسالة بدل فتح التطبيق فوق تخزين غير مستقر. النتائج المتأخرة تُهمل بعد إغلاق النشاط.
9. `getModelList` يقدّم مخطط JSON ذا نسخة محددة. يعرض `model-catalog.js` القائمة في الإعدادات عبر `textContent` ويحدّثها عند نجاح الاستيراد. لا monkey-patching لدالة render؛ أُضيف حدث `daftari-render`.
10. بيانات القائمة snapshot غير قابلة للتعديل؛ طلب القائمة لا ينتظر قفل الاستيراد الطويل. فتح ملف النموذج نفسه محمي بالقفل حتى لا يقع في الفجوة بين عمليتَي rename.

## بنية المعاملة

لا تغيير لمواقع النموذج والمشروع القائمة؛ لا حاجة لترحيل بيانات المستخدم في هذه الدفعة:

```text
files/imports/
  model-ar/model.tar.gz       # النموذج النشط
  proj/...                   # المشروع المحفوظ، غير منشور للـ WebView
  .transactions/
    model-ar/                # أو proj
      work/input.zip
      work/expanded/...      # Vosk فقط
      ready/...              # النسخة الجديدة كاملة
      journal-v1             # علامة PREPARED مع fsync
      backup/...             # النسخة السابقة، أثناء الاستبدال
```

### الترتيب

- استرجاع أي معاملة سابقة معروفة.
- تجهيز `work` و`ready` وكتابة الملفات والتحقق منها دون تعديل النسخة الحالية.
- sync لملفات `ready` ثم كتابة journal ومزامنته.
- نقل النسخة الحالية إلى `backup` إن وُجدت.
- نقل `ready` إلى موقع التثبيت: **هذه نقطة الالتزام**.
- تنظيف المعاملة. إذا فشل التنظيف بعد الالتزام فلا يُعلن الاستيراد فاشلًا؛ تعاد محاولة التنظيف عند التشغيل/الاستيراد التالي.

### قاعدة الاسترجاع

| الحالة المتبقية | الإجراء |
|---|---|
| وجهة قديمة + work/ready، بلا backup | الحفاظ على الوجهة وإزالة التجهيز غير الملتزم |
| backup موجود والوجهة غائبة | إعادة backup إلى الوجهة، ثم تنظيف التجهيز |
| الوجهة وbackup موجودان | الوجهة الجديدة هي الملتزمة؛ تنظيف backup |
| تثبيت أول بلا وجهة، work/ready فقط | إزالة الملفات الجزئية؛ لا تثبيت تلقائي لمحتوى غير ملتزم |
| وجهة موجودة وready اختفى بعد النقل | الحفاظ على الوجهة وتنظيف المعاملة |

إذا تعذّر استرجاع backup فلا يُحذف. لا تُحذف مجلدات `backup-*` القديمة مجهولة الوجهة من تنفيذ ما قبل المعاملات؛ لا يمكن استنتاج ما إذا كانت تخص نموذجًا أو مشروعًا بأمان.

**حد الضمان:** اختُبرت حالات انقطاع العملية بمحاكاة حالات نظام الملفات عند حدود النقل، وليس قتل التطبيق على هاتف. fsync لملفات البيانات والعلامة موجود؛ directory fsync غير منفّذ، لذلك لا وعد بسلامة مطلقة عند انقطاع الطاقة أو عطب القرص. لا دعم لاستيراد متعدد العمليات؛ التطبيق الحالي أحادي العملية.

## المساحة وحدود الاستيراد

- 1 GiB لملف الإدخال وللحجم المفكوك، و30,000 عنصر.
- فحص الحجم الحقيقي أثناء النسخ والفك، إضافة إلى فحص metadata الأولي.
- تقدير مساحة إضافية للفك والضغط قبل التنفيذ، ثم فحص المساحة أثناء الكتابة.
- ترك هامش 16 MiB؛ هذا تقدير تحفظي، لا حجز مسبق يمنع التطبيقات الأخرى من استهلاك القرص. فشل الكتابة يُبقي النسخة السابقة.
- ملفات خارج جذر Vosk الواحد مرفوضة. مثلًا ZIP يضع `model/am/final.mdl` ومعه ملف خارج `model/` سيُرفض؛ يُنصح باستيراد ZIP النموذج نفسه.
- `am/final.mdl` غير الفارغ لا يثبت دقة التعرف أو اللغة أو سلامة كل ملفات المحرك؛ الاختبار الفعلي للمحرك ما زال مطلوبًا.

## عقد قائمة النماذج

Android يعيد:

```json
{
  "version": 1,
  "models": [{
    "id": "vosk-active",
    "name": "Vosk",
    "engine": "vosk",
    "assetUrl": "model-ar/model.tar.gz",
    "size": 123456,
    "state": "installed"
  }]
}
```

- هذا مثال بنيوي وليس نموذجًا مضمّنًا أو حجمًا حقيقيًا.
- `installed` تعني وجود الملف، **لا جاهزية التعرف**.
- عدم وجود نموذج يعيد مصفوفة فارغة؛ لا سجلات وهمية.
- `DaftariBridge.getModelList()` يتحقق من version/error ثم يعيد المصفوفة للواجهة.
- نسخ Android القديمة دون هذه الطريقة تعيد قائمة فارغة عبر fallback، ولا تكسر الصفحة.
- لا مسار Android داخلي في JSON.
- القائمة تعرض slot Vosk واحدًا كما كان التخزين السابق؛ لم تُنفّذ بعد إدارة نماذج Vosk متعددة.
- Whisper يبقى في IndexedDB وبواجهته الموجودة، ولا يظهر كنسخة مكررة في القائمة Native.
- `importedList()` التوافقي أصبح يعرض نموذج Vosk النشط فقط، لا ملفات المشروع أو المكتبات القديمة.

## تحقق نُفّذ فعلًا

### واجهة وبنية

```sh
npm ci
npm test
```

**9 اختبارات ناجحة**: تشمل إقلاع الواجهة والإعدادات، الفصل بين Android/domain، الجسر، قائمة JSON، تحديثها بعد الاستيراد، رفض البروتوكول غير الصالح، وعرض أسماء تحتوي HTML كنص غير قابل للتنفيذ.

### التخزين على JVM

```sh
./tools/test-storage.sh
```

نجحت مجموعتان:

- `StorageSafetyTest`: 1045 تحققًا (معظم العدد فحوص padding بايتًا بايتًا في TAR، وليس 1045 سيناريو مستقلًا).
- `ImportLifecycleTest`: 46 تحققًا تشمل الاسترجاع قبل/بعد نقطة الالتزام، التكرار الآمن للاسترجاع، التثبيت الأول، ZIP تالف وCRC غير مطابق، فشل مزود الملفات، الإلغاء، استيراد غير صالح لا يزيل النموذج السابق، الحدود، والمسارات.

الاختبارات استخدمت نظام ملفات Linux حقيقيًا وملفات ZIP/TAR مولّدة مؤقتًا. لا تحل محل ContentResolver أو Android Instrumentation.

لأن JDK الكامل لم يتوفر في PATH، شُغّلت عبر Java 17.0.9 runtime (`jdk4py 17.0.9.2`) ومترجم ECJ 3.16. يمكن تشغيلها في هذه الحالة بـ:

```sh
JAVA=/path/to/java ECJ_JAR=/path/to/ecj.jar ./tools/test-storage.sh
```

على جهاز فيه JDK 17+ لا حاجة إلى ECJ. لم تُضف ملفات runtime أو JAR إلى المستودع.

### فحص تجميع مصادر Android

```sh
ANDROID_JAR=/path/to/android-35/android.jar ./tools/check-android-sources.sh
# أو مع JAVA وECJ_JAR إن لم يكن javac متوفرًا
```

نجح تجميع جميع مصادر التطبيق مقابل API 35، مع 3 تحذيرات deprecation تخص ألوان شريطي النظام و`setDatabaseEnabled`. استُخدم ECJ مع source/target 11 لأن الكود الحالي لا يتطلب بناء جملة Java 17؛ إعداد Gradle الأصلي بقي Java 17.

مصادر أدوات الاختبار المؤقتة: ECJ من ملف `org.eclipse.jdt.core.jar` في processing/processing4 (blob `b749e518b8a065856cc948363db71253fb855f84`)، ومرآة API 35 في Sable/android-platforms (blob `2d6652edf0fb6046a23638f3a2f2c6246c745b08`). هذا فحص أنواع API فقط وليس اعتمادًا على مرآة بدل SDK الرسمي للإصدار.

**لم يُبنَ APK ولم تُنفذ dex/resources/lint أو اختبارات جهاز.** سلسلة Gradle/Android SDK الكاملة لم تتوفر. محاولات تنزيل JDK من GitHub Release تعثرت عند مضيف الملفات؛ لذلك استُخدم مسار الاختبار البديل الموصوف أعلاه.
