# الدفعة الخامسة — مخطط الدفتر والحفظ والاستعادة

## التنفيذ

- `www/js/ledger-schema.js`: وحدة مستقلة بلا DOM أو تخزين؛ تنسخ المدخلات، تفحص البنية ومعرّفات الحسابات والسجلات والمبالغ الصحيحة الآمنة والتواريخ وتوزيعات السداد، ثم تُرحّل v1 إلى v2 دون تعديل الأصل. تُرحّل أيضًا المبالغ في سلة المحذوفات وسجل التعديلات وحدود العملاء. الترحيل المتكرر لا يضاعف المبالغ.
- يظل **schemaVersion = 2**؛ تغيّر تنسيق ملف التصدير إلى **formatVersion = 2** لتغطية الحقول الدلالية كلها بالـ SHA-256، بما فيها رقم المخطط والحساب النشط. ملفات formatVersion 1 القديمة تظل قابلة للقراءة، بما فيها checksum القديم ذي 32 خانة. هذا فحص اتساق لا توقيع ولا إثبات لمصدر الملف. التصدير الجديد يحتاج WebCrypto؛ لا رجوع إلى checksum ضعيف عند غيابه.
- الفاتورة ذات المبلغ صفر صالحة بعد الإرجاع الكامل. المراجع إلى عناصر السلة تُحتسب عند الفحص. الروابط المفقودة نهائيًا بسبب حذف قديم تُعاد كتحذيرات، لا تُصلح بإنشاء سجلات وهمية ولا بحذف المال. الاستعادة تُظهر وجود هذه التحذيرات. التوزيع بين عميلين مختلفين أو تجاوز مبلغ الدفعة يُرفض؛ لا تُفرض قاعدة جديدة تمنع كل حالات الفواتير المعدّلة بعد الدفع القديمة.
- `storage.js`: IndexedDB مصدر الحقيقة، مع طابور حفظ يلتقط نسخة البيانات وإعدادات التشفير والمفتاح عند الاستدعاء. فشل التشفير أو غياب المفتاح يرفض العملية ولا يكتب نصًا واضحًا بدلها. فشل عملية لا يعطّل الطابور اللاحق.
- الهويات القديمة محفوظة: قاعدة `dafter-db`، المخزن `kv`، المفتاح `db`، ومفاتيح localStorage القديمة. تُضاف `__security` إلى السجل المحفوظ لتثبيت إعدادات فك القفل مع البيانات في المعاملة نفسها؛ `__enc` يظل غلاف النص المشفر. المرآة في localStorage ليست مصدر نجاح الحفظ، وفشلها لا يلغي معاملة IndexedDB الناجحة.
- تغييرات PIN وتعطيل القفل وتعديل بيانات البصمات تنتظر حفظ الإعدادات والبيانات معًا قبل تثبيت الحالة في الذاكرة. المفتاح المستعاد قابل لإعادة التغليف لتغيير PIN؛ هذه ليست عزلة للمفتاح عن JavaScript داخل التطبيق.
- الاستعادة تتحقق أولًا، ثم تحفظ السجل البديل والنسخة السابقة في معاملة واحدة. النسخة السابقة في مفتاح `safety-backup` داخل IndexedDB؛ تُشفّر إذا كانت الجلسة مشفرة. الحفظ العادي لا يحذفها. تغيير إعدادات القفل يمحو نسخة الأمان القديمة لتجنب الاحتفاظ بنص واضح أو بيانات تحتاج إعدادات مفتاح قديمة. تُنظف نسخ localStorage القديمة الواضحة عند الحفظ المشفر، قدر استطاعة API التخزين.
- لا يتغير الدفتر المعروض ولا تظهر رسالة نجاح الاستعادة قبل اكتمال المعاملة. الحفظ المتداخل يلغي الاستعادة المحروسة إن كانت معاملتها ما زالت قيد التنفيذ؛ فحوص النسخة تمنع تثبيت الحالة المستعادة فوق تعديل أحدث.
- الاستعادة القديمة عبر QR وإعادة التهيئة تستخدمان مسار الاستعادة نفسه، بدل الإسناد المباشر والحفظ غير المنتظر.
- الإقلاع يقرأ IndexedDB أولًا، ويقفل عند وجود سجل مشفر حتى دون مرآة localStorage. فشل القراءة أو مخطط غير مدعوم لا يؤدي إلى إنشاء دفتر فارغ فوق البيانات. فشل فك التشفير يبقي القفل ويتيح إعادة محاولة الفتح.

## التحقق المنفذ

`npm test`: **63/63** ناجحة، منها **23** اختبارًا جديدًا في `tests/persistence.test.cjs`.

الاختبارات تستخدم fake-indexeddb وWebCrypto الحقيقي في Node، وتشمل:

- الترحيل دون تعديل الأصل، تكراره، السلة والتعديلات والحدود.
- مبالغ غير آمنة ومفاتيح خطرة ومعرّفات مكررة ومخطط مستقبلي وتوزيعات غير صالحة.
- ترتيب حفظ مع تشفير مؤخر، ونسخة البيانات الملتقطة عند الاستدعاء.
- فشل التشفير وغياب المفتاح وفشل التخزين واستمرار الطابور.
- انتظار الاستعادة، وحفظ نسخة الأمان، وتراجع المعاملة بعد طلب الكتابة فعليًا.
- تداخل الحفظ أثناء التشفير وأثناء معاملة الاستعادة.
- checksums القديمة والجديدة ورفض التصدير الجديد بلا WebCrypto.
- فتح مشفر دون localStorage، ومفتاح خاطئ، وفشل قراءة، ومخطط تالف.
- ربط إعدادات القفل بالسجل، وفشل تغييرها، وامتلاء مرآة localStorage، وإعادة تغليف المفتاح.

لم تُعدّل مصادر Java في هذه الدفعة. أرقام JVM وفحص API 35 في وثائق الدفعات السابقة تخص تشغيلاتها السابقة، ولم تُعَد هنا. لم يُبنَ APK ولم تُنفّذ اختبارات جهاز في هذه الدفعة.

## الحدود والعمل المتبقي

- `save()` يعيد Promise ويرصد الرفض، لكن كثيرًا من شاشات التعديل القديمة ما زالت تغيّر الذاكرة وتعرض رسائلها بشكل تفاؤلي؛ لم تُحوّل كل العمليات المالية إلى معاملات واجهة تنتظر الحفظ وتتراجع عند الفشل. ضمان الانتظار الجديد يخص الاستعادة وتغييرات القفل.
- هذا الطابور خاص بنسخة الصفحة الحالية، وليس بروتوكول تنسيق بين عدة تبويبات أو عمليات WebView. ضمان المعاملة هنا هو ضمان IndexedDB، لا اختبار انقطاع طاقة على جهاز فعلي.
- لا fallback صامت إلى localStorage عند تعطل IndexedDB؛ يتوقف الإقلاع بأمان. واجهة تشخيص/تصدير خام/استعادة من نسخة الأمان عند تعطل الإقلاع لا تزال مطلوبة. نسخة الأمان الداخلية ليست بديلًا عن ملف احتياطي خارجي.
- التصدير JSON غير مشفر عمدًا، حتى عند قفل الدفتر؛ يجب حفظ الملف في مكان موثوق. checksum ليس حماية ضد تعديل متعمد. حد اختيار ملف JSON هو 32 MiB؛ حدود QR وفك الضغط تحتاج تدقيقًا منفصلًا.
- دعم WebAuthn/PRF والبصمة يحتاج إصلاحًا واختبارًا كاملًا على الأجهزة؛ حفظ بياناته ذريًا لا يثبت صلاحية بروتوكول البصمة الحالي. PIN ذو أربعة أرقام لا يوفر مقاومة قوية لهجوم غير متصل؛ لا ادعاء بتدقيق أمني شامل.
- المخطط ليس تدقيق XSS لجميع القوالب. الروابط التاريخية المفقودة تُحفظ مع تشخيص، ولا يُدّعى استرجاع سجلات حُذفت سابقًا.
- ما زالت بوابة الإصدار تشمل Gradle/APK، Android 5 و14، الترقية من بيانات حقيقية، دوران الشاشة وموت العملية، الأذونات والنماذج الفعلية وقياسات الشاشة المختلفة.
