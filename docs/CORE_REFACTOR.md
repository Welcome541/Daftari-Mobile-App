# إعادة بناء الأساس — سجل التنفيذ

**آخر تحديث:** اكتملت [الدفعة السابعة: المعاملات الإدارية وسلامة السلة](ADMIN_PHASE_7.md). الاختبارات الحالية **100/100**. لم يكتمل البناء أو التحقق على الأجهزة؛ البصمة وOCR وبقية فصل القوالب لا تزال ضمن العمل الباقي.

هذه وثيقة تنفيذ للفرع `arena/7beb4250-daftari-mobile-app`، وليست إعلانًا باكتمال الخطة كلها.

## 1. القرارات التي تمنع كسر الإصدار المثبت

- إبقاء `applicationId` واسم نشاط التشغيل `MainActivity` واسم نطاق WebView كما هي.
- إبقاء مسارات `files/imports/model-ar` و`files/imports/proj` في هذه الدفعة. تغييرها إلى `files/models` و`files/projects` يحتاج ترحيلًا قابلًا للاسترجاع؛ نقلها مباشرة يجعل النماذج القديمة تختفي.
- إبقاء مفاتيح LocalStorage وقواعد IndexedDB الحالية، ومنها قاعدة نموذج Whisper.
- محركا Vosk وWhisper يعملان في المتصفح/WASM حاليًا. لم نضف أصناف Java فارغة باسم `VoskEngine` و`WhisperEngine`؛ هذه ستكون واجهات مضللة قبل تحديد عقد المحرك وتنفيذه.
- فصل ملفات JS بوصفها classic scripts مع ترتيب تحميل ثابت أولًا. التحويل المباشر إلى ES modules سيكسر المراجع العامة ومعالجات الأحداث الحالية.
- لا تشفير شكلي للنماذج أو تصغير للكود: ذلك لا يعالج أمن المسارات ويصعّب التشخيص. تشفير بيانات دفتر المستخدم الحالي محفوظ دون تغيير.

### Web

أصبح `index.html` نحو 3.3 KB بدل نحو 2.1 MB. لم تُحذف المكتبات؛ استُخرجت كما هي إلى `lib/` مع تعليقات التراخيص الأصلية.

- `css/app.css`: CSS السابق، و`responsive.css` باقٍ كما هو.
- `js/icons.js`, `i18n.js`: الأيقونات والترجمة.
- `js/storage.js`: التخزين والتشفير والنسخ الاحتياطي الموجود.
- `js/ledger.js`: حسابات الدفتر؛ `ledger-schema.js` للمخطط والترحيل، و`ledger-edits.js` لمعاملات التعديل، و`recovery.js` للتعافي.
- `js/state.js`: إنشاء البيانات والترحيل والوصول إلى البيانات.
- `js/ui-core.js`: التنسيق والتنقل والحالة المرئية.
- `js/speech.js`: خدمة الصوت، و`js/speech/controller.js` للعقد والحالات والإلغاء، و`js/speech/engine-factory.js` لاختيار adapter. تفاصيل ضمانات وحدود التنفيذ في سجل الدفعة الثالثة.
- `js/screens.js`, `voice-ui.js`, `actions.js`: تقسيم أولي للواجهة والعمليات مع إبقاء السلوك.
- `js/app.js`: ربط أحداث صفحة الدخول وتشغيل التطبيق.
- `js/bridge.js`: المكان الوحيد الذي يقرأ واجهة `window.Daftari` الأصلية.

لا تزال قوالب الشاشة الديناميكية تحتوي معالجات inline، وبعض الملفات كبيرة. إزالة ذلك وتوحيد الحالة مرحلة تالية، لا نعتبر مجرد استخراجها إتمامًا لفصل مسؤوليات الواجهة.

## 3. عقد الجسر الحالي — RPC v2

`Daftari.dispatch(JSON)` يستقبل أربع عمليات مسموحة فقط: `models.list` و`model.import` و`project.import` و`contact.pick`.

كل طلب يحمل `version/type/id/method/params`، وكل رد يحمل المعرّف نفسه و`progress/success/error`. طبقة JS تقدم Promises ومهلًا وإلغاءً، وNative يضمن ردًا نهائيًا واحدًا للطلب المقبول. عمليات المنتقي الملغاة تظل محجوزة حتى وصول نتائجها القديمة أو انتهاء العامل؛ الإلغاء لا يضمن التراجع عن استيراد مكتمل.

`RequestRegistry` لدورة حياة الطلب، و`OperationGate` لحجز العملية الفعلية، و`native-actions.js` لرسائل الواجهة وتطبيق النتائج. لا يكتب transport في نموذج العميل مباشرة.

تفاصيل JSON والتوافق مع v1 وحدود الإلغاء والمهل في [وثيقة الدفعة الرابعة](BRIDGE_PHASE_4.md). أُبقيت طريقتا القراءة القديمة في Native؛ بقية عمليات الواجهة الجديدة تستخدم RPC.

## 4. تقوية التخزين والأمان

- رفض `..` بوصفه مقطعًا، المسارات المطلقة، backslash traversal، NUL، drive paths.
- استخدام canonical path مع فاصل المجلد لمنع التباس أسماء المجلدات المتشابهة.
- حد 64 مقطعًا للمسار لتقليل خطر الاستدعاء العودي العميق.
- حد 1 GiB لملف ZIP ولحجم المحتوى المفكوك، و30,000 عنصر.
- الفحص الأولي باستخدام `ZipFile` metadata بدل فك ZIP كامل بلا حد في `findRoot`.
- رفض تعدد جذور `am/final.mdl`، بما في ذلك جذر فارغ مع جذر فرعي.
- رفض `am/final.mdl` الفارغ، أسماء الملفات المكررة بعد التطبيع، وعناصر مجلد ZIP التي تحمل بيانات.
- فحص الحجم الفعلي أثناء الفك، لا الثقة بالـ metadata وحدها.
- الكتابة في staging، ثم حفظ نسخة سابقة واستبدالها؛ الفشل قبل التثبيت لا يمس النموذج السابق.
- إلغاء نسخ/فك/ضغط الاستيراد عند إغلاق النشاط، مع تجاهل callbacks المتأخرة.
- منع استيراد JS/WASM عبر منتقي Vosk. لا يمكن للملفات القديمة في `imports/lib` تجاوز المكتبات المضمنة بعد الآن.
- الملف المستورد الوحيد المنشور عبر أصل التطبيق هو `model-ar/model.tar.gz`؛ مشاريع HTML المستوردة لا تُنشر مع الجسر.
- حظر التنقل الخارجي في نسختَي `shouldOverrideUrlLoading`، بما فيه Android 5؛ السماح بروابط الهاتف/الرسائل/البريد عبر تطبيق خارجي.
- طلبات WebView للميكروفون والكاميرا تُقبل من أصل التطبيق فقط، مع رفض الموارد غير المعروفة.

### تغيير سلوك مقصود

المسار القديم كان يسمح باستيراد مكتبات تشغيل، وبعرض ملفات مستوردة من أصل يمتلك JavascriptInterface. أُغلق هذا المسار. استيراد المشروع Native أصبح حفظ ZIP فقط مع رسالة واضحة؛ تشغيل مشروع غير موثوق يحتاج WebView معزولًا بلا جسر وبلا وصول إلى بيانات التطبيق. لا نعتبر ذلك تنفيذًا نهائيًا لإدارة مشاريع دفتر المستخدم.

### حدود لم تُحل بعد

- عولج انقطاع العملية بين عمليتي rename في الدفعة الثانية مع recovery على عامل خلفي. لا نضمن انقطاع الطاقة لأن directory fsync غير منفّذ. النسخ القديمة مجهولة الوجهة `backup-*` من التنفيذ السابق لا تُحذف تلقائيًا.
- أُضيفت حدود مساحة تعتمد على القرص مع هامش 16 MiB، وتقدير للفك والضغط. لم تُضف حصص منفصلة قابلة للضبط لكل محرك.
- التحقق من `am/final.mdl` لا يثبت أن النموذج صالح للتعرف أو عربي؛ يلزم اختبار تحميل حقيقي.
- Whisper لا يزال يستورد GGML في IndexedDB عبر التنفيذ السابق، وليس عبر ModelManager Native.
- لا يدّعي هذا التغيير أن جميع مواضع HTML الديناميكي/الاستيراد في تطبيق الويب خضعت لتدقيق XSS شامل.

## 5. الاختبارات الحالية

```sh
npm ci
npm test
```

في الدفعة الأولى نجحت 6 اختبارات آلية. أصبحت 9 بعد الدفعة الثانية، ثم 28 بعد الدفعة الثالثة، ثم **40** بعد الدفعة الرابعة. تفاصيل الاختبارات الحالية في سجل الجسر. الاختبارات الأساسية:

1. تحليل صياغة جميع ملفات Java — **ليس تجميع Android**.
2. منع منطق ZIP والكتابة المباشرة وJavascriptInterface داخل الأنشطة.
3. حصر الوصول المباشر للجسر Native في `bridge.js`.
4. صحة صياغة ملفات JS وعدم وجود script/style blocks داخل HTML.
5. تحميل الأصول محليًا، إقلاع التطبيق، وعرض الإعدادات وواجهة Whisper عبر jsdom.
6. تفويض طرق الجسر وأحداث الرد وعرض رسالة خطأ تحتوي HTML كنص آمن.

اختبارات JVM المستقلة **شُغّلت ونجحت في الدفعة الثانية** باستخدام Java 17 runtime وEclipse compiler؛ يمكن تشغيلها على JDK 17+ مباشرة:

```sh
./tools/test-storage.sh
```

تغطي path traversal وsymlink escape وZIP متعدد الجذور وتحقق Vosk وصياغة TAR. تحتاج JDK 17+ ولا تحتاج Android SDK.

بناء Android:

```sh
./gradlew assembleDebug
```

محاولة الدفعة الأولى توقفت لغياب Java. في الدفعة الثانية توفر Java runtime ومترجم بديل وملف API 35، ونجح فحص تجميع مصادر Android. لم تتوفر سلسلة Gradle/Android SDK الكاملة، ولم يُنتج APK ولم يُختبر Android 5 أو Android 14. jsdom ليس متصفحًا ذا layout أو WebView، ولا يثبت سلامة التسجيل أو WASM أو أبعاد الشاشة.
