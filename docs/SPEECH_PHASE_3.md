# الدفعة الثالثة — عقد الصوت ودورة حياة التسجيل

## المنفّذ

الصوت ما زال يعمل داخل WebView عبر مكتبات Vosk/Whisper المضمّنة. لم نضف أصناف Java تدّعي تنفيذ تعرف Native غير موجود. أصبح للمحركات عقد حقيقي في JavaScript، مع فصل بين دورة التسجيل وبين دفتر المستخدم.

### الملفات

| الملف | المسؤولية |
|---|---|
| `js/speech/controller.js` | عقد SpeechEngine، Controller، حالات EngineState، جلسة واحدة، مهلة التجهيز والتسجيل، إلغاء النتائج القديمة |
| `js/speech/engine-factory.js` | اختيار adapter Vosk/Whisper/Web Speech وتوحيد طرقه |
| `js/speech.js` | SpeechService الخاصة بالتطبيق، قراءة إعدادات الاختيار وربط أحداث الخلفية |
| `lib/vosk-adapter.js` | تحميل المكتبة والنموذج، KaldiRecognizer، امتلاك الميكروفون وAudioContext والـ Worker |
| `lib/whisper/engine.js` | نموذج IndexedDB، WASM، التسجيل والتحويل إلى PCM والتعرف وإدارة الاستدلال الملغى |
| `lib/whisper/ui.js` | بطاقة إعدادات Whisper واستيراد/إزالة النموذج فقط؛ لا استبدال لدوال التسجيل أو render |
| `js/voice-ui.js` | استقبال النص وتقديم معاينة وتصحيح يدوي، دون استدعاء المحركات أو فتح الميكروفون مباشرة |
| `web/WebViewHost.java` | إرسال حدث خلفية ثابت إلى JS قبل `WebView.onPause()` |

## العقد

كل adapter يقدّم:

```text
initialize() -> Promise
start({ language, onStarted, onPartial }) -> session
session.result -> Promise<string>
session.stop() -> طلب إنهاء التسجيل واستخراج النص
session.cancel() -> إلغاء النتيجة وإغلاق الصوت
release() -> إلغاء التحميل الجاري وتحرير الموارد المملوكة الممكن تحريرها بأمان
```

`result` تُحسم مرة واحدة: نجاح أو فشل أو `AbortError` عند الإلغاء. توقّف التسجيل لا يعني أن نتيجة Whisper جاهزة؛ تبقى الجلسة مشغولة إلى أن تنتهي معالجة النص.

حالات controller:

```text
idle → initializing → starting → listening → stopping → ready
                                      ↘ نجاح مبكر → ready
أي مرحلة نشطة → error عند الفشل
أي مرحلة نشطة → idle عند الإلغاء
release → released
```

- `starting` تشمل انتظار إذن/توصيل الميكروفون.
- يبدأ عداد التسجيل عند `onStarted`، لا عند الضغط على الزر أو أثناء تحميل النموذج.
- مهلة تجهيز المحرك والميكروفون: 90 ثانية.
- حد التسجيل في الخدمة: 30 ثانية.
- انتظار النتيجة النهائية لـ Vosk/Web Speech بعد الإيقاف: 3 ثوانٍ.
- مهلة استدلال Whisper: 10 دقائق؛ بعدها يتطلب إعادة فتح التطبيق قبل إعادة استخدامه.
- الطلب الثاني أثناء وجود جلسة يُرفض بـ `BUSY` بدل فتح ميكروفون آخر.
- الإيقاف أثناء التجهيز يلغي الطلب؛ النتائج أو صلاحيات الميكروفون التي تصل لاحقًا لا تعيد فتح التسجيل.

الخدمة تختار حسب الإعدادات الموجودة دون تغيير مفاتيحها: Whisper إذا كان `dafter2.whisper.enabled=1`، وإلا Vosk إذا كان `sec.vosk` مفعّلًا، وإلا محرك المتصفح. لم يُضف fallback صامت من محرك محلي فاشل إلى خدمة قد تكون متصلة بالإنترنت. عند اختيار محرك المتصفح تظهر ملاحظة بأنه قد يستخدم خدمة عبر الإنترنت.

## إصلاحات دورة الحياة

### Vosk

- إزالة مهلة الانتظار الثابتة 300ms؛ البدء ينتظر تجهيز النموذج فعلًا.
- لا تحميل تلقائي للنموذج عند إقلاع الصفحة؛ التحميل عند الحاجة.
- الاحتفاظ بمرجع `Vosk.Model` أثناء التحميل، حتى يمكن إنهاء Worker بدل تركه مخفيًا داخل Promise.
- إلغاء إصدار تحميل قديم يمنع تثبيته بعد بدء تحميل جديد.
- معدل العينة المستخدم في recognizer يطابق AudioContext الفعلي.
- إغلاق tracks وAudioContext، فصل العقد، واستدعاء `recognizer.remove()` عند النهاية/الإلغاء/الفشل.
- انتظار نتيجة الإيقاف بمهلة محددة؛ نتائج recognizer القديم لا تؤثر على جلسة لاحقة.

### Whisper

- إغلاق الميكروفون قبل الاستدلال، وحفظ معدل العينات قبل إغلاق AudioContext، ثم تحويل الصوت إلى 16kHz.
- فحص الإلغاء بعد وصول الإذن وبعد `AudioContext.resume()`؛ إغلاق stream المتأخر بدل إعادة التسجيل.
- الوعد المعلّق يُرفض عند الإلغاء؛ لا يبقى دون نتيجة كما في التنفيذ السابق.
- انتظار سطر `whisper_print_timings: ... total time =`، لا أول سطر timings الذي قد يكون مجرد وقت تحميل النموذج.
- استدلال واحد فقط؛ لا تُنسب مخرجات عملية ملغاة إلى عملية جديدة.
- منع استبدال/إزالة نموذج ما زال قيد التجهيز أو الاستخدام.
- حفظ/حذف IndexedDB يكتمل قبل إسقاط النموذج السابق من الذاكرة؛ الفشل لا يمحو حالة النموذج العامل أولًا.
- لم يتغير اسم قاعدة IndexedDB أو المخزن أو المفتاح.
- لا تعاد كتابة `window.Module` عند فشل/انتهاء مهلة تحميل runtime قد لا يزال يعمل؛ تتطلب الحالة غير الموثوقة إعادة الفتح.

### حد مهم: إلغاء Whisper ليس hard abort

واجهة WASM الحالية لا تقدم معرّفًا لكل نتيجة أو وسيلة موثوقة لإيقاف الحساب Native الجاري فورًا. لذلك:

1. يُغلق الميكروفون وتُرفض نتيجة جلسة المستخدم فور الإلغاء.
2. يُحتفظ بمرجع العملية الحسابية دون تسليم نتائجها إلى الواجهة.
3. يُرفض بدء Whisper جديد أو تعديل نموذجه حتى تصل علامة اكتمال العملية السابقة.
4. لا يُحرر instance لا يزال يستخدمه worker؛ يؤجل التحرير إلى الاكتمال.
5. إذا انتهت المهلة أو حدث عطل غير موثوق، يُمنع إعادة استخدام المحرك حتى إعادة فتح WebView/التطبيق.

هذا يمنع اختلاط النصوص وتحرير ذاكرة مستخدمة، لكنه **لا يَعِد بإيقاف CPU فورًا** ولا باستعادة كامل ذاكرة WebAssembly المتنامية دون إعادة إنشاء runtime. الاعتماد على علامة `total time` يحتاج اختبارًا فعليًا مع runtime والنماذج على الجهاز؛ الاختبارات الآلية أدناه تحاكي هذه الواجهة.

## تغييرات الواجهة

- إزالة فتح ميكروفون ثانٍ لمقياس الصوت. بقيت حركة موجة زخرفية؛ ليست قياسًا حقيقيًا لشدة الصوت. يمكن إضافة مستوى صوت لاحقًا عبر تدفق المحرك نفسه.
- لصق نص من محرك خارجي لا يبدأ التسجيل أصلًا.
- نتيجة الصوت تُعرض للمراجعة؛ لا تُسجّل عملية مالية تلقائيًا.
- مغادرة شاشة التسجيل أو قفل التطبيق أو ذهابه إلى الخلفية تلغي الجلسة وتمنع النصوص المتأخرة من تعديل الواجهة.
- دعم `visibilitychange` و`pagehide` وحدث Android `daftari-background`؛ عند إغلاق WebView نفسه يتولى Android التخلص من سياقه.
- أُزيل monkey-patching لـ `startRec/endRec/cancelRec/render` من Whisper. بطاقة الإعدادات تستخدم `daftari-render`.
- إصلاح حدث استيراد Whisper: تمرير `event.currentTarget` بدل كائن الحدث الذي لا يحتوي `files`.
- إضافة تنفيذ واضح لـ `retryRec` واستبدال مسار callbacks العالمية مثل `voskOnText` بالوعود المقيّدة بالجلسة.

## تحقق نُفّذ

```sh
npm ci
npm test
```

**28 اختبارًا ناجحًا**:

- 5 اختبارات بنية وصياغة وفصل مسؤوليات.
- 15 اختبارًا لخدمة الصوت والـ adapters: الإلغاء أثناء التهيئة، ازدواج الطلبات، المهل، النتائج المتأخرة، رفض الإذن، تحرير الموارد، تبديل الجلسات، وحماية Whisper أثناء الاستدلال.
- 8 اختبارات واجهة/JSDOM تشمل التسجيل حتى المعاينة، عدم الحفظ التلقائي، الخلفية، لصق النص، واختيار ملف Whisper.

اختبارات الصوت تستخدم ميكروفونًا وAudioContext ومحركات وهمية حتمية؛ تُشغّل كود adapters نفسه، **لكن لا تشغّل WASM حقيقيًا ولا تختبر دقة التعرف العربي**. نموذج الاختبار ملف صناعي للتأكد من مسار التخزين والتهيئة، وليس نموذج تعرف صالحًا.

أُعيد أيضًا بنجاح:

- `tools/test-storage.sh`: مجموعتا التخزين السابقتان، 1045 و46 تحققًا.
- `tools/check-android-sources.sh`: تجميع المصادر مقابل API 35، مع 3 تحذيرات deprecation سابقة.
- `git diff --check`.

لم يُبنَ APK ولم يتوفر جهاز Android؛ لذلك لم تُختبر أذونات Android الفعلية أو دقة النص أو توقيت رسائل runtime أو الأداء والذاكرة على الهاتف.

## المتبقي قبل اعتماد الصوت للإصدار

- تشغيل Vosk عربي وWhisper GGML فعليين، والتحقق من علامة اكتمال Whisper الحالية ومن الأحداث الدقيقة للمكتبة.
- اختبار Android 5/14 مع WebView مناسب، إذن مرفوض/ملغى، تأخر الإذن، تبديل التطبيق أثناء التسجيل والاستدلال.
- قياس الذاكرة أثناء التبديل بين المحركين وأثناء نماذج كبيرة.
- استبدال بروتوكول stdout في Whisper بواجهة نتيجة ذات jobId أو worker مخصص قابل للإلغاء إذا أُعيد بناء runtime.
- إزالة بقية global state وinline handlers من قوالب الواجهة ضمن مرحلة فصل UI التالية.
- استكمال بروتوكول الجسر requestId/timeout واختبارات الملفات والمشاريع، ثم بناء APK واختباره فعليًا.
